## 投递、确认与恢复

`pending → delivered → acknowledged → completed`。活跃工作收到立即消息时变为 `paused`，先处理新消息，空闲时再领取暂停工作。暂停消息不会抢占另一个立即消息，因此不会互相反复打断。立即模式是 Hub 的协作式优先投递；真实提供商的取消语义必须由适配器另行确认。

排队模式只在空闲时领取；消息写入与任务分配的唤醒消息使用事务。每个 Agent 一次只有一个 active 消息，支持 sender + request_key + recipient 去重，重复 key 携带不同内容会被拒绝。群发各收件人分别确认。用户收件箱是可查看的聊天记录，不需 Agent 式领取确认。

租约 30 秒，活跃心跳续租；心跳超过 15 秒未更新显示离线。租约到期或服务重启后，未完成消息重新领取，投递语义为至少一次：消费者必须以消息 ID 幂等，不能声称 exactly-once。任务进度和 note 可作为业务检查点。v0.1 不恢复模型内部推理状态。

Supervisor 是不调用模型的常驻 Python 进程，每秒检查子进程与调度心跳；崩溃或持续不健康会自动重启并退避，最长 30 秒。SQLite WAL 保存任务、消息、进度、审批、预算和审计；OS 锁防止同一数据目录的双实例。即使九个 Agent 全部空闲，也由这个循环接收新消息并唤醒模拟 Agent。Supervisor 自身或机器停止时不可能凭空运行；可选安装登录启动：

```powershell
.\Register-Startup.ps1
# 取消登录启动：
.\Register-Startup.ps1 -Remove
```

该脚本未自动执行。它建立当前用户登录任务，非 Windows 系统服务，未登录时不会启动。休眠/关机期间不工作，恢复运行后检查实际状态；不推算模型额度必然恢复。

## MCP 接入

```powershell
$env:HUB_URL = 'http://127.0.0.1:8765'
$env:HUB_TOKEN = (Get-Content .\data\credentials.json -Raw | ConvertFrom-Json).'sol-1'

```

  "mcpServers": {
    "agent-hub": {
      "command": "C:/Path/To/python.exe",
      "args": ["-m", "hub.mcp"],
      "cwd": "C:/Path/To/agent-message-hub",
      "env": {"HUB_URL": "http://127.0.0.1:8765", "HUB_TOKEN": "AGENT_SPECIFIC_TOKEN"}

## DeepSeek：可执行的受控文本 Connector

只访问 `https://api.deepseek.com` 官方 `/models` 与 `/chat/completions`，模型固定 `deepseek-flash`，无自动模型替代。先验证模型列表。当前环境未设置密钥，因此未发起真实推理；连接器通过假的官方响应测试，不能等同真实 API 成功。

在**启动服务的同一个 PowerShell** 中设置环境（不要将密钥粘贴到聊天、源码或 README；本项目不自动读取 .env）：

```powershell
$env:DEEPSEEK_API_KEY = Read-Host 'DeepSeek API key' -MaskInput
$env:HUB_ALLOW_REAL = '1'
.\Start-Hub.ps1
```

`-MaskInput` 需要 PowerShell 7；Windows PowerShell 5.1 可用 `Read-Host -AsSecureString` 并在本地转换为进程环境变量。已有服务需先停止并用新环境重启，不会自动拾取另一个终端的环境。

在仪表盘设置总预算（美元美分）→ 准备具体请求 → 核实官方输入/输出单价并输入本次保留上界 → 勾选确认 → 执行。每次授权仅可用一次，五分钟有效，绑定持久化的确切 prompt 摘要；最多 1000 字符输入和 256 输出 tokens，明确关闭 thinking，不开放工具、搜索、任意命令或图片。

预算是本地累计保留账本：已批准、运行中、已完成和结果不确定的调用均占用全额，避免并发超卖；未执行批准可以撤销释放。输入费用上界按 UTF-8 字节加 framing 余量及用户核实的单价保守估算。它依赖提供商遵守输出上限和正确单价，不是提供商侧强制美元封顶；建议同时在官方账户设置支出限制。网络超时/服务重启时运行中调用标 uncertain，不自动重试、不释放预算，需人工在提供商核对。

真实 DeepSeek 只是受控单次文本执行，不接管模拟 inbox，也没有 shell/file 工具。主界面“模拟模式”仍指协作消费者，DeepSeek 调用结果单独记录在审批面板。未批准时后台不会产生任何真实模型消费。

## 本地安全与备份

服务仅绑定 IPv4 loopback；Host/Origin 校验、Bearer 身份授权，无 CORS；界面用 textContent 显示外来文本，无外部脚本。凭证和数据属于本机用户，不能抵抗有同等本地文件权限的恶意进程。`data/credentials.json` 包含所有身份密钥，保留在受保护用户目录，不要分享、打包或提交。审计是普通本地 SQLite 记录，不是防篡改账本。停止服务后备份整个 `data/`；在线备份请使用 SQLite backup API，不能只复制主 db 忽略 WAL。

### 经理强停与项目静置

经理可用 `project_stop_task(task_id, reason)` 直接停止本项目成员任务：未启动的任务取消；执行中的任务终止 Hub 持有的本地进程树、撤销本轮工具权限并释放占位，可立即重新派工。旧执行晚到的回复不能覆盖停止状态、写入 API 会话历史或改变新任务状态。已经发送给提供商的远端请求仍可能计费。

在「与项目经理沟通」上方点击「允许项目静置」，只关闭该工作流的定期经理巡检；按钮随后变为「恢复定期巡检」。该操作不会停止 Agent、发送消息、改变项目状态或取消定时器。主动消息和显式定时器仍按原规则执行。开关持久化，重新打开面板仍保留。


经理提交 `project_complete` 时，只要本项目其他成员仍在运行或中断中，就暂不允许提交（经理自身除外）；排队、等待额度和已结束的异常记录不拦截。经理可等待成员结束，或主动用 `project_stop_task` 强停后再提交。成功提交时取消本轮剩余排队项，再冻结演示。返回 `completed=true` 表示经理已确认项目完成；只有 `design_review_ready=true` 才表示演示已发布到审阅入口。若发布失败，返回 warnings 并显示具体发布错误；重启时会自动恢复旧版已完成但未发布的有效演示，无需调用模型。页面覆盖由经理确认，不再以规划 ID 与页面 ID 必须逐字一致作为门槛。


### 会话目录切换、额度耗尽和计时器清理

OpenCode/Ori 按原会话目录加载持续上下文；当前项目切换到产品目录时，将新目录添加为受支持的 additionalDirectories，并在新任务中明确当前绝对路径。不会清空上下文、重放历史任务或自动重试已改派的失败任务。加载时重放的历史对话不显示为本轮新回复。实施任务切到 Build；独立检查与成员间质询使用 Plan。当前经理在已批准项目内发给成员的工作消息按任务执行，并参与文件范围排队。

额度按提供商连接与模型适用窗口判断，Claude/GPT 的 Antigravity 共享窗口不会使健康 Gemini 变灰。额度耗尽时，Agent 卡片和右侧极简状态灰显；派工在启动模型前取消，并通过常规经理汇报通道发送原因，不再弹红色额度面板。若提供商在调用时才明确返回额度耗尽，也将该任务取消；不会把并发限流/普通 HTTP 429 冒充额度耗尽。低于 10%、耗尽、恢复的原通知流程保留。新的正额度观测会解除灰显。

一次性计时器投递后从活动调度表和界面移除；周期计时器保留下一次到期。结束/取消记录进入最多 500 条的历史存储，投递审计保留，重启不会重复投递。


### 正式开发：Git worktree 与集成

需要本机 Git for Windows。Hub 在正式项目启动执行时准备本地 Git 仓库，经理使用项目主目录，每个成员使用独立 worktree 与持久分支。演示阶段保持原流程。成员可同时修改同一文件，不再使用跨成员文件占用排队；同一成员仍按消息顺序执行。

成员完成后使用 MCP `project_git(action="commit", message="改动摘要")`，平台在执行结束后也会补存提交，并把分支、提交和工作目录加入结果证据。失败或中断的修改原样保留，不自动算成成功。只读检查不自动提交文件。

经理用 `project_git(action="status")` 查看分支，`project_git(action="integrate", agent="成员ID")` 集成已提交的工作，在项目主目录运行集成测试。若有冲突，现场保留；经理修复后执行 `git add`，再调用 `project_git(action="commit")` 保存合并。没有自动选边、强推、清空文件、额外验收门禁或远端上传。

首次并行前会将主目录现有源码保存为基线提交，不会重置已有改动。构建缓存、运行凭据及证书私钥默认不加入新提交。已有仓库中原先跟踪的文件不会被擅自移除。分支目录位于 Hub 数据目录下的 `git-worktrees`，重开应用继续使用；后续同项目同成员继续原会话。任务中的原项目绝对路径会转向本轮 worktree。


### 快速启动与虚拟机
默认桌面发布使用 `desktop/hub_desktop_fast.spec` 生成目录版：主程序与旁边的 `_runtime-*` 文件夹必须一起保留，不可只复制 EXE。目录版免除每次自解包，运行文件按版本隔离，更新不会替换旧进程正在读取的资源。单文件构建仍保留在 `desktop/hub_desktop.spec`。

主界面先由同源启动服务提供；后台初始化完成后自动登录并解锁后台操作。项目列表底部的进度按真实阶段完成数显示，不伪造虚拟机开机百分比。无凭据时虚拟机阶段跳过，Hub 仍可正常使用。保存凭据后下次启动会自动请求必要的 Windows 权限、启动所选虚拟机并等待 PowerShell Direct 可用，然后连接、校验传输并部署端服务。虚拟机不会阻塞聊天和项目设置。新虚拟机需要已安装 Windows 和正确的管理员凭据；图形桌面服务还需要用户登录 Windows，不自动绕过登录或解锁。

Agent 页显示虚拟机电源及连接状态，并提供开机、正常关机、需确认的强制关机；电源操作只开放给用户面板，不开放为模型 MCP 工具。用户主动关机后，本次运行不会不断自动重启它。当前虚拟机未作实际关机回归测试，以免打断项目；按钮交互和队列逻辑用隔离测试验证。


### 虚拟机首次连接与无人值守

配置中的“自动配置无人值守”默认开启，仅作用于选择的 Hyper-V Windows 虚拟机。连接验证成功后自动部署桌面服务、配置 Windows 自动登录、建立独立的防休眠电源方案，并在该账号的桌面服务启动时关闭屏幕保护锁定、动态锁定及本地空闲锁定。密码通过 PowerShell Direct 的凭据对象传入，存入虚拟机 Windows LSA secret，不放进进程命令行、脚本、普通 Winlogon DefaultPassword 值或日志。管理员仍可读取 LSA 凭据，虚拟机控制台可直接访问已登录桌面。

自动登录从下次 Windows 启动生效；部署不强制重启、不退出当前用户、不停止现有任务。首次连接时若停在登录界面，可先登录一次，或在适当时间重启虚拟机。Windows 更新过程仍需等待，手动锁定或组织强制策略不保证能够自动解锁。宿主机的登录、锁屏、UAC、睡眠及 Windows 更新设置不变。

关闭方式：取消“自动配置无人值守”并重新连接。Hub 删除自己配置的自动登录 secret、关闭自动登录、恢复保存的锁屏设置和原电源方案；已保存的连接偏好会供下次启动使用。若不希望保留连接密码，再点删除已保存凭据。配置失败会单独报告，不把命令连接成功伪称为无人值守设置成功。


虚拟机命令通道现在会在 Windows 更新或重启使 PowerShell Direct 会话失效后自动重建连接，失败时逐步延长重试间隔，最长 60 秒。重连只恢复连接，不重复执行旧请求；执行中断线的请求标为结果未知，需先核查现场。凭据无效时停止尝试并提示更新，避免反复尝试锁定账号。用户在本次运行期间手动断开或关闭虚拟机后，不会被重连逻辑重新连接或开机。

状态会区分等待 Windows 启动、自动重连、命令已连接、等待桌面就绪、需要更新凭据。管理员权限标识只在命令连接有效时显示。桥接进程使用 Windows PowerShell 自带模块路径，避免继承 PowerShell 7 的模块导致凭据命令无法加载。


平台自动通知使用“平台”发送者，并在经理输入中以“平台通知：”标明；转交的成员消息保留成员来源，用户单条原文不附加无关说明。群聊显示真正的平台通知，隐藏例行调度信封，不把通知执行结果冒充平台的回复。项目邮箱以 platform_notice 标识此类通知，消息来源不会增加任何执行权限。

升级时会依据工作流关联修复旧版自动调度通知的错误 user 发送者，保留实际用户消息与提供商原始输入记录。历史上下文不清空，已发送给模型的旧提示词不伪造重写。

### 独立桌面窗口

桌面版把演示审阅、成果查看、模型原始输入、配置、接入向导和 Agent 管理/详情打开为真实的 Windows 窗口，可移动、缩放，并与工作台同时操作。项目创建/设置/重命名、删除确认、强制关机和接入测试确认使用有父窗口的模态窗口，先确认或关闭后才能继续操作该父窗口。下拉菜单和右键菜单继续作为菜单。

桌面附属窗口的标题栏只保留系统关闭按钮，移除最小化、最大化和页面内重复的叉号；主窗口使用工作台自定义标题栏。额度速览使用侧栏锚定悬浮卡片（点击外部或 Escape 收起），按提供商展示百分比环及相对恢复时间。界面通过底色与轻阴影区分层级，键盘焦点仍清晰可见。

正式交付的 project_complete 第一次只返回测试核对问题，第二次携带 confirmation.comprehensive_tests 与 confirmation.vm_ui_tests，说明全面测试、虚拟机模拟输入验证的结果或未测原因。测试结论由经理判断，平台不自动跑测试或以报告内容判通过；仍执行原有的忙碌成员限制。静态演示只调用一次 project_complete，无需二次确认或交付文件夹链接；正式制作仍需链接。
批量成员/平台通知附 UTC+8 时间标记；单条用户原文不增加前缀，完整创建时间可由 project_mailbox 查询。
演示预览测量包含居中页面的左侧负溢出；适应窗口不恢复旧平移偏移，手动缩放仍保留滚动与批注。

## 经理直接打断与队列管理
当前项目经理可以用 `send(mode="immediate")` 或 `project_queue(operation="interrupt", agent=..., instruction=..., request_key=...)` 直接中断成员轮次并优先处理新内容：停止该轮本地执行、撤销旧轮工具权限，旧结果不能覆盖新轮。原工作不记成功，其它排队项保留；不解除用户的紧急停止锁。
`project_queue(agent=...)` 返回执行中及待执行项的完整内容；`operation="edit", item_id=..., instruction=...` 修改待执行输入，`reorder, item_ids=[...]` 调整顺序（省略项顺延），`delete, item_id=...` 取消某项并保留历史。经理只管理本项目已授权成员。排序同时作用于准备派工、真实执行器和原始消息领取，并持久化；运行中输入不改写，可直接 interrupt。编辑保持原工作目录与已声明文件范围，范围需变更时由经理重新派工。外部前置任务仍须满足。

建议独立复核者默认从本项目已允许参与的非经理成员中选取，已选的有效成员保持不变；无人时留空，不回退到经理。新增/切换经理、删除成员及旧运行项目的建议值均遵循此规则。此选项仍只是建议，不自动派发复核或新增完成门禁。

## 启动时提前请求虚拟机授权
已保存虚拟机连接时，面板启动即在独立线程发起管理员桥接/连接请求，不再等待后台初始化或页面就绪信号（原来最多等待 30 秒）。主界面与后台继续加载；已有兼容桥接直接复用，未保存连接不请求授权。取消启动授权后不因后台就绪再次请求，可在配置中手动重试。此版本采用提前请求 UAC 的方案。

## 经理回复去重与模型级额度状态
讨论历史已包含的经理回复，不再重复显示同一执行编号的 `execution:<run>:user` 回执；原记录保留，独立消息和用户重复发送的相同内容不按文本去重。
提供商明确拒绝（包括 OpenCode 的 Free usage limit reached）即使没有额度百分比，也会进入模型级耗尽状态、取消未启动任务并通知经理。新讨论成员快照及运行时能力列表明确标注 quota_exhausted，未知恢复时间不假定恢复；排队讨论实际启动前刷新状态，保持原参与范围。该类告警与已知百分比告警一样去重、恢复后重置；显示剩余比例未知，不伪造百分比。平台告警给用户的副本标为平台来源。

## 演示资源打包
静态演示发布时自动将项目内相对路径的 CSS（含本地 @import 和 CSS 图片/字体引用）及 img 资源内嵌进 HTML；冻结目录和带 CSP 的预览不再依赖原项目资源路径。缺失资源会说明具体路径，避免生成已发布但无样式的页面。启动时可修复尚未确认、源页面未改变的旧资源遗漏快照，保留旧冻结目录，已确认基线不改动。


### 项目文件清理与 Git 查看

设置采用左侧分类、右侧内容布局。在「项目存储」选择「清理文件」，先查看关联目录并确认，再清理本机主目录、独立 Git 工作区（包括未提交内容）、演示版本及展示附件。正在执行或尚有运行中 Agent 的项目不能清理；暂停/结束并等待执行结束后可操作。未移除项目清理后仍在项目列表中；向经理发送新需求时自动重建空目录，保留原有对话和模型会话，旧任务归档且不重放。文件永久删除；虚拟机内副本、提供商账号配置、全局审计记录不在此范围。共享目录与存储根目录保留，文件占用等清理失败会逐项显示，可释放占用后重新清理。容量统计包含外部独立工作区。

主页右侧「Git 分支与提交」展示真实 Git 提交树及 Agent 分支对应关系，最近 80 条提交，展开时每 5 秒刷新，收起停止读取。切换项目会切换仓库；请求失败时保留上次记录。这个入口只读，不提交或合并代码。


同一时间只执行一个项目。其它项目的消息、到期提醒及额度恢复会暂缓启动；当前项目暂停或结束并释放运行中的执行后才能切换。连接测试不算项目执行。群聊输入框默认收起，通过右下角图标展开/收起，收起保留草稿。标题栏已移除前进/后退、目录、额度与设置的重复图标；对应功能仍可通过侧栏或项目菜单使用。


VM push 支持覆盖已有目录：按相对路径逐文件更新，避免重复嵌套目录；不删除目标的其它文件。completed 返回文件数量、字节数与 SHA256 核对结果。queued 只代表入队，须用 request_id 查询最终结果。exec 是客机服务会话的命令通道，不代表交互桌面渲染能力；GUI 启动失败应依据桌面通道及原始日志判断。
