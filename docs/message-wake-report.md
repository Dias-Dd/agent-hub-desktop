# 普通消息唤醒修复

根因：旧路由只有active项目能将消息转为执行，blocked项目的用户消息保留为held，且既有held消息不会再次检查。缩短prompt不能解决此执行门禁。

现在普通消息可在没有活动项目、blocked、paused、stopped（无紧急锁）时创建独立question对话。消息原文绑定原消息ID；同一消息只生成一次执行，忙碌Agent依旧串行接收。已知项目沿用project会话范围，直接对话注入简短项目状态。对话使用只读权限，不恢复项目、不授权派工或重放历史执行。active项目的正常经理消息驱动派工路径不变。

紧急停止锁、模型启用配置、订阅额度、调用次数与DeepSeek独立费用预算继续生效。被拦截消息保留，wakeups.note写具体原因；旧held用户消息会在巡检重新检查，条件未变不重复写审计。Agent互发仍遵守项目参与者、消息数和跳数授权，生成的执行回执不自动互相唤醒，防止回执循环。

DeepSeek独立对话使用原API授权和费用账本，不开放实施工具。验证使用模拟提供商，160项测试通过，包括blocked不恢复但唤醒、无项目多提供商唤醒、幂等、配置恢复重试、停止锁拦截，以及DeepSeek对话预算和无工具。实际模型可用性仍由提供商确认。


后续真实联调修正：早期曾分离普通对话与经理会话；此策略已由项目上下文更新替代：同一项目共用记忆，各回合仍核验对应权限，并带入项目状态及最近说明。普通对话不调用工具。工具格式错误保留会话及原始错误，不自动清空上下文或重试失败回合。

用户显式workflow_wake现在可恢复blocked项目：先验证原授权、期限和停止锁，跳过已经结束的经理回合处理游标，释放未处理收件箱，并新建一次经理检查。旧执行不重放。第一阶段中断任务必须核查产物，不视为成功。本次按用户要求启动真实Argon经理回合以推进第二阶段，费用仍受原授权约束。

本次回归163项测试通过。真实联调已确认Argon新会话通过官方init权限核验，view_file与call_mcp_tool出现DONE；另通过真实stdio MCP握手调用project_status成功。第二阶段派工结果以Hub任务台账为准。


收件箱与验收竞争修复：经理声明完成时如有pending事件，创建下一轮消息处理，不消耗验收纠错次数，也不将正常新消息当成项目故障。巡检另外检查batched但pending的用户消息；项目blocked时，在原授权与停止锁检查通过后唤醒真正的经理回合，跳过已经结束的旧经理处理，不重放执行者任务。新发给blocked项目经理的用户消息同样触发这条路径，不再降级成不能派工的独立对话。用户暂停、停止、授权失效和预算边界继续有效。
