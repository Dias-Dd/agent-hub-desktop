# Argon 项目调度与消息修复

2026-10-18 更新。此前只支持逐任务批准，Agent 间普通消息不能自动启动真实执行器。这是原来 sol-2 待领取的原因，不是模型故障。

## 使用

打开工作台，使用顶部「向 Argon 提需求，由它分工、巡检和汇报」。填写需求与验收标准，选择参与者，设置项目调用次数和有效期，确认授权。每次项目调用包含 Argon 的分工、工作 Agent 的执行、Argon 的验收。最小闭环是 3 次调用。

提供商原有次数预算同时生效。若不足，使用入口旁的「设置 Codex 次数预算」「设置 Google 次数预算」调整并明确确认；不会自动提高额度。预算按实际调用记录，不等于剩余订阅百分比，也不是 token/美元硬上限。

普通消息先入队，不自动授权模型。历史待领取消息可点击「查看并授权执行这条消息」，直接启动接收方并沿用原消息 ID；任务消息则从任务列表授权。真实执行结束，平台给用户和原发送方发送幂等回执，回传不依赖模型调用 MCP。

## 自动流程

1. Argon 按持久化的项目经理角色 Prompt 定义验收标准并返回结构化分工。
2. 调度器严格校验允许的 Agent、次数、授权有效期、提供商配置授权 ID。校验后持久化子任务与唤醒消息，并提交到真实执行队列。
3. Supervisor 持续检查执行记录。等待时不产生重复推理；同一时间运行一个真实任务。
4. 所有本轮执行结束，自动再次启动 Argon，将实际状态和结果摘要交给它验收。Argon 可在剩余预算内安排修复，或报告验收完成。
5. 每轮汇报写入用户消息、项目进度和审计。结果不确定、格式错误、超范围、预算不足或到期时阻塞并报告，不盲目重试。

Argon 的分工/验收通过结构化协议交给平台处理；没有假装 CLI 已接入 Hub MCP。Hub MCP 的现有工具仍可用于已配置的外部客户端。DeepSeek 尚无完整任务执行器，不允许参加项目自动分工。

## 恢复与限制

项目、阶段、子任务和真实执行全部保存在 SQLite。已准备未提交的阶段重启后继续提交；运行中连接丢失按原执行器规则标记 uncertain，不重放。每个项目步骤绑定唯一 task_id，避免重复分工。停止项目会取消未启动任务，并按提供商接口停止运行中的任务；Antigravity 不能保证服务端取消。

调度器在启动前检查项目仍然 active、未到期、原授权未变。项目到期不再授权新调用，已经启动的调用受原任务时间预算约束。用户确认的是该需求范围内由项目经理提出的后续任务，不是允许其他任意消息自动执行。完全访问仍意味着当前 Windows 用户权限；工作目录不是安全边界。

进度由 Argon 汇报；completed 表示其已验收，平台不把单个模型回合结束当作项目完成。结果摘要有限长，大项目仍需写可检查的文件、测试结果与验收说明。当前采用串行批次；批次中的任务应互不依赖，需要依赖时分多轮安排。

## 验证

- 历史 sol-1 → sol-2 消息真实启动后 completed，返回「测试完成：2+2=4」，原消息未复制，已由平台回传 sol-1。
- 真实闭环：Argon（Gemini 4 Argon Medium）分工、sol-2（GPT-6.1 Sol）执行、Argon 验收，全部 completed。任务不涉及文件修改或命令执行。
- 原始脱敏记录见 argon-workflow-live-test.json。
- 52 项回归测试通过，包含项目恢复、禁止重复提交、预算、有效期、权限变化、未授权参与者、结果不确定及回执幂等。

本轮验证后原有提供商任务次数预算为 Codex 0、Google 1；这是 Hub 次数授权用量，并非订阅额度耗尽。开始新项目需在页面重新确认足够的次数预算。
