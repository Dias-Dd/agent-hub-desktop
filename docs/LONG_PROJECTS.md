# 多日项目、并行调度与统一启动面板

2026-10-18 更新。

## 本次根因

旧版全局只有一个真实执行槽，项目最多30回合、授权一天、提供商最多100次调用。这些限制用于早期联调，不适合多日项目。

最新用户项目中 Argon 实际分派了 sol-1，但后台缺失 Codex 的 PATH，返回“未安装官方 Codex CLI”，随后转交 Flash。已加入本机官方桌面应用安装目录的发现逻辑，并统一供执行器、诊断和初始化向导使用。已在禁用 PATH 查找的情况下实际启动官方 App Server，读到 ChatGPT 登录和 gpt-6.1-sol / gpt-6-astra；未发起推理。证据：codex-path-diagnosis.json。历史失败记录保留，不自动重放。

## 新面板

主页首先显示“启动项目”，填写项目目录与需求，选择参与者，设置总工作回合、授权天数和并发数。单模型调试和历史执行记录折叠，更多检查/消息/时限设置也折叠；停止全部按钮始终可见。

默认是7天、2000回合、并发3，默认选择两个 GPT Sol、GPT Astra 及三个 Gemini Flash，Opus 可选。修改表单本身不会启用这些设置，必须勾选确认再启动。

启动时对所选提供商统一保存目录、单任务时间和回合数授权，沿用各自已经保存的访问权限；每个提供商使用新的授权ID，旧执行记录保留。随后项目总回合再约束全部提供商，合计不会变成两倍。若配置步骤失败，页面会显示错误，已经成功保存的配置仍保留，但不会假装项目启动成功。

经理收到参与者模型、职责、提供商剩余次数和并发上限，提示优先把核心编码分配给 sol-1/sol-2，测试交给 flash-3，复杂技术判断交给 astra；没有固定要求每轮必须消耗所有顶级模型。

## 上限

| 设置 | 当前上限 |
| --- | --- |
| 项目总工作回合 | 10000 |
| 每个提供商授权次数 | 10000 |
| 项目授权有效期 | 30天 |
| 同时执行的 Agent | 8 |
| 同一 Agent 同时执行 | 1 |
| 单项任务最长时间 | 24小时 |
| 项目消息唤醒设置 | 最多10000 |
| 消息链层数 | 最多32 |

回合是模型工作轮次，不是美元、token 或订阅额度。DeepSeek 的美元 API 预算仍是独立设置，且暂时没有开发任务执行器。

## 并行与恢复

两个提供商使用同一个 SQLite 事务调度计数。独立身份可以同时运行；忙碌身份的后续任务不会挡住其他空闲身份。每项执行有独立的客户端、进程树与停止目标，停止一个 Agent 不会因为共享客户端变量而误杀另一个。

一个批次的工作全部结束再进行检查、经理验收；有依赖的任务需要分成不同批次。并发不意味着所有步骤一直同时运行，分工与最终验收阶段只有项目经理运行是正常现象。

Codex 和 Antigravity 官方额度耗尽时，在尚未启动推理的前提下持久化 waiting_quota，并在预计恢复后重新读取实际额度，恢复才启动。服务重启、连接断开或已提交推理的执行结果不确定时，不自动重放可能已改动文件的工作。无法登录、接口不支持、授权到期、严重风险和总回合耗尽仍会停止并汇报。

## 当前实际限制

- 多个执行器共用项目目录，没有自动 Git worktree 隔离。经理需划分不同文件范围；复杂修改仍需审查合并冲突。
- 这是支持多日授权的本地 v0.1，不是已通过数日连续运行验收的生产调度器。尚未完成多日压力与故障实测。
- 电脑需保持运行，Hub/Supervisor 需保持运行。没有擅自修改 Windows 休眠或自启动设置。
- 新版内置 CLI 的中途 MCP 沟通仍未动态接入，主动消息在本轮结束提交；外部已连接 MCP 的客户端可以途中发送。

## 测试

66项回归通过。新增验证：不同身份能同时进入执行；同一身份不能重叠；忙碌身份不阻塞另一个身份；7天/5000回合授权；10000次提供商授权及24小时时限；额度等待时不启动推理；Codex无PATH仍可发现安装；HTTP/MCP、停止锁与恢复旧测试。并发调度测试使用模拟提供商，本次没有新增真实推理调用，也不宣称供应商侧的并发额度或连续多日可靠性已经实测。
