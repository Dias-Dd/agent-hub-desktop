# 网页渲染与系统通知设置

## Agent 网页渲染

打开 **设置 → Agent 网页渲染**。这里选择的是 Agent `browser_render` 截图工具使用的浏览器，主程序仍使用原来的内嵌网页引擎。

- **自动选择**：优先使用已安装的 Edge、Chrome 或 Chromium；都没有时尝试应用专用 Chromium。
- **已安装的浏览器**：下拉列表显示检测到的 Chromium 内核浏览器，包括受支持安装位置中的 Brave。
- **指定 Chromium 主程序**：输入或浏览选择主程序文件。Windows 选择 `.exe`；macOS 可直接选择浏览器 `.app`，也可选择应用内 `Contents/MacOS` 的可执行文件。Firefox 和 Safari 不支持当前的截图协议。
- **应用专用 Chromium**：点击“下载并安装 Chromium”，等待安装完成，然后在下拉列表选择它并保存。下载来源为 Chromium 官方快照，不是稳定版 Chrome。数据位于应用数据目录下 `browsers/chromium`，不替换系统浏览器，也不读取个人浏览器资料。

“测试渲染”使用已保存的选择实际生成一张本地测试页面截图，不调用模型。自定义主程序丢失时会报错，不会悄悄换浏览器。

下载有进度、取消和失败提示，校验官方提供的文件长度和摘要后再解压；失败或取消保留之前安装的版本。安装后不会自动更新，也不会自动更改浏览器选择。下载时需要能访问 Google 的 Chromium 快照存储，遵循本机可用的网络代理设置。

选择浏览器不会改变现有页面范围、联网限制或项目工具授权。

## 系统通知

打开 **设置 → 系统通知**：

- 总开关控制系统通知。
- 发送时机可选“始终通知”或“仅应用在后台时通知”。
- 分别控制产品演示就绪、正式项目完成、项目阻塞或需要处理。
- “发送测试通知”是一次显式测试，即使关闭总开关或应用位于前台也会发送，便于检查系统权限。该操作不调用模型。

设置在实际发送前检查。被关闭或因前台状态跳过的事件不会在之后集中补发，历史完成事件也不会在启动时重播。聊天记录、长期记忆更新卡片和应用内状态提示不受这些开关影响。

通知仍受 Windows/macOS 的系统权限、免打扰和专注模式影响；macOS 需要从正式应用包启动并允许通知。Windows 使用通知中心，失败时尝试托盘提示。

macOS 的通知设置页提供“允许 macOS 通知”入口，仅用户点击时请求系统授权。若之前拒绝，可在系统设置 → 通知 → Agent Hub 中修改。应用前台时的“始终通知”通过原生 UNUserNotificationCenter 展示回调适配，后台策略仍在宿主发送前判断。测试通知先入队，再查询该次事件的 OS 接受/拒绝结果；OS 接受不代表用户已经看见横幅。
