# 发给 Mac 上 Codex 的提示词

使用前：在 Mac 上获取 `macos-port` 分支，让 Codex 打开仓库根目录，然后复制下方分隔线后的提示词。此分支包含交接文档；`main` 保持 Windows 0.2.1 发布状态。

首次获取：

```sh
git clone --branch macos-port https://github.com/Dias-Dd/deskfellows.git deskfellows
cd deskfellows
```

若已有本地仓库，先检查并保留未提交修改，然后获取并切换到远程 `macos-port` 对应的本地分支，不要强制重置。

---

请接手 Deskfellows 的 macOS 移植开发。这是新会话，你没有 Windows 上的聊天历史，请以交接文档和实际源码为依据，不要假称记得先前讨论。

先阅读仓库根目录的 `AGENTS.md`、`README.md`、`docs/MACOS_HANDOFF.md`、`docs/HARNESS_INTEGRATION.md` 和 `docs/LONG_TERM_MEMORY.md`，再检查工作树、当前分支、macOS 版本、CPU 架构及可用开发工具。

Windows 当前发布版是 `v0.2.1`，基线提交为 `333843055f0cefc9b6ca438aeca23800dbb9b77b`。目标是在 `macos-port` 分支开发原生可运行的 Mac 桌面版，保留 Windows 版和现有项目业务、模块化 Harness 接口及前端设计。如果未检出这个分支，先检查本地情况；不要覆盖已有修改或重置用户工作。

先审查启动链路和平台依赖，简短说明实际发现的阻塞，再分阶段实施。优先完成无虚拟机也能使用的桌面应用，并打通至少一种实际可用的 Harness；之后完善设置引导、凭据、系统通知和打包。WebView2、Win32、DPAPI、Windows Job Object 和 Hyper-V 都需要明确的平台处理。不要把浏览器打开网页当成最终 Mac 桌面版，也不要用未验证的成功提示代替真实功能。

虚拟机后端已经由我确定为 **Tart**，请按此实现，不必重新询问选择哪一种虚拟机。先检查这台 Mac 的架构、系统版本与 Tart 兼容性；若不支持，说明真实阻塞，不自行换成 UTM 或 Parallels。保留 `project_vm` 对外工具接口，在底层增加 Tart 后端，支持安装检测/引导和虚拟机管理，并逐项验证命令、文件传输、截图和桌面操作。缺失能力如实显示，不要伪造支持；普通项目仍可跳过虚拟机。
