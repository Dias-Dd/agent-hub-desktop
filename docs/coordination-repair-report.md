# Coordination, adapters and manager task stop repair

## Findings and behavior
1. Cross-agent tasks could write the same files concurrently, and checks could inspect partial files. Added durable resource scopes and dependencies. project_assign accepts write_paths/read_paths; relative/absolute aliases normalize under the project directory. Known file references in older prompts are inferred conservatively; unknown scopes serialize. Same-file writers and related readers wait for local termination; unrelated scopes retain parallel execution. Legacy prepared queues are backfilled in sequence order before workers start; no dependency cycles are created. Timer-triggered implementation tasks also participate. Scope declarations coordinate scheduling; they are not an OS file sandbox or a promise to control arbitrary native writes.
2. Managers could only cancel queued tasks. New project_stop_task(task_id,reason) is scoped to the current manager and project; available through all provider tool definitions and MCP routing. Running clients receive the existing stop request; after a grace period the owned client is closed. A living worker retains its blocker. Orphaned local runs with an explicit stop request become interrupted, not completed; message/Agent leases are reconciled. No model acknowledgement is required, no global stop latch is created, and unknown remote cancellation/billing is disclosed. Missing/retired executors do not prevent cancelling unstarted tasks. Acceptance still requires actual verification, not just an empty queue.
3. CodeBuddy npm shim uses an extensionless Node entry. Resolve its actual shebang entry under node_modules and pass an argument vector directly; keep rejection of unsafe arbitrary batch shell text. Real local --version succeeded: 2.171.0, no inference.
4. Codex configured approvalPolicy=never but did not configure the Hub MCP approval mode. Added official run-local mcp_servers.agent_hub.default_tools_approval_mode=approve. No global user config or unrelated server policy changed. Existing server run/project permission checks and tool filters remain. Official installed app-server config/read returned approve; no inference. Documentation: https://learn.chatgpt.com/docs/config-file/config-reference (MCP server defaults and per-tool approval modes).
5. Screenshot launcher could return zero without PNG and cleanup could fail on Windows after a successful PNG. Added a fallback using isolated Edge/Chromium and the public DevTools protocol, no account/browser session reuse. Both routes clean frozen-app DLL/environment effects. Temporary profile cleanup cannot invalidate a generated PNG. Fallback blocks HTTP/HTTPS loads, verifies PNG and propagates concrete errors. Packaged smoke option verifies real DevTools capture without inference.
6. Group chat duplicated source reports, manager scheduling copies and successful wakeup receipts. Projected view now shows one readable result with risk/evidence, suppresses internal manager delivery copies, and keeps the full raw report accessible. Database history is not deleted. Existing display-name fixes included.
