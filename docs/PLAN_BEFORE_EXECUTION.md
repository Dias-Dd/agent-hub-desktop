# 先与 Argon 讨论，再确认执行

2026-10-18 更新。默认主页不再一提交需求就开工。

## 使用

1. 在「先和 Argon 讨论计划」填写需求和拟用的参与者、目录、天数、回合数、并发数。
2. 勾选仅讨论授权，点击「发送需求给 Argon · 仅讨论」。此授权最多20轮、24小时，仍受已有 Google 执行次数和官方额度约束；不会重设项目执行授权或启动其他 Agent。
3. Argon 先提问题或给出可阅读计划。你可以在下面聊天框继续讨论、调整范围。计划可实施时，界面会列出当前版本、首批具体任务，以及对应运行设置和访问权限。
4. 阅读完后，在聊天框准确输入「按计划执行」。系统核对当前版本、计划摘要、设置和权限；确认通过后才保存执行授权并启动你审阅的首批任务。

「可以」「继续」以及模型自己写出的确认词不会启动项目。修改设置后应先发消息让 Argon 更新计划；旧版本确认、等待回复时确认和权限变化都会被拒绝。重复确认已经启动的同一计划不会重复创建项目。

## 实现边界

- 讨论是单独 purpose=discussion 的 Argon 回合，不创建 workflow_steps。模型 JSON 中的 tasks 仅作为待审计划存储，没有执行权限。
- 官方 CLI 使用 --mode plan 和 --sandbox，移除 --dangerously-skip-permissions；拒绝 always-proceed 的 init，讨论过程中请求工具也停止本地进程。讨论输出格式异常、模型调用失败或结果不确定时，计划不可批准，不自动派活。
- 只有本地 user 身份的 plan_chat 接口可确认；MCP 中不开放确认工具，模型输出、内部消息和其他 Agent 身份都不能批准。
- 批准以 session、revision 和计划内容摘要绑定，首批任务原样写入工作队列，不重新调用 Argon 生成另一版首批计划。后续检查与修复仍须遵守已批准的总体计划和运行范围。
- 全部首批任务在同一 SQLite 事务准备；确认键持久化，重复请求或重启不会重复启动同一版本。运行中断结果不确定仍不重放。
- 权限、模型调用费用和官方限制仍沿用已有机制。讨论也消耗 Google 订阅额度；确认后执行阶段使用所选提供商的订阅额度。主面板会明确显示尚未授权实施，避免把待审计划误显示成项目已完成。

## 验证

75项回归测试通过。覆盖：讨论不派任务、模型输出确认词不生效、问题/无效计划不可执行、修改版本或设置/权限后旧确认失效、用户确认后只执行原计划、重复确认幂等、重启保留待审状态、结果不确定不执行、CLI计划模式参数、HTTP完整讨论与确认路由。均使用模拟提供商，未新增真实推理调用；本次没有宣称已对真实 Argon 规划模式完成一次推理验收。首次实际对话会验证提供商返回的模式，拒绝不符合讨论权限的返回。

只读 CLI 检查：官方内置 /usage 在 --mode plan --sandbox 参数下成功返回（不调用推理），见 plan-mode-cli-probe.json；该结果不包含 init，仍需首次实际讨论验证权限模式。

长度校验修复：单项计划任务说明最多6000字；空说明或超长说明会指出具体任务和实际长度。用户 v2 的1337/1025/947字任务已经从既有回复无损恢复为待审阅，未重新调用模型，未启动执行。新增回归后77项测试通过。
