# 经理长期记忆

长期记忆在同一应用数据目录内跨项目共享。更换经理或创建新项目后，当前经理会自动收到记忆快照，不需要翻找旧聊天。

参考了 [Hermes 的持久记忆设计](https://hermes-agent.nousresearch.com/docs/user-guide/features/memory)：区分用户资料与经验笔记、限制容量、通过工具明确保存。Agent Hub 使用事务数据库和版本检查，以支持多个项目的经理并发访问，以及用户回滚和锁定。

## 使用

打开 **设置 → 长期记忆**：

- **用户偏好**：稳定的沟通方式、明确的个人偏好，最多 3,000 字。
- **经验笔记**：经过验证、适合以后复用的经验，最多 6,000 字。
- **保存记忆**：保存两栏内容并新建版本。内容不会自动截断。
- **锁定记忆**：经理仍可读取，但无法增删修改。用户仍可编辑、回滚或解锁。
- **版本历史**：按时间分页，显示修改者、时间和操作。选择后先预览，再点击“回滚为此版本”。回滚会新建版本，原历史和当前锁定状态保留；也能回滚到初始的空记忆。

界面不会轮询记忆，也不会在后台刷新时替换草稿。如果保存时记忆已被其他项目的经理更新，会提示冲突并保留草稿。先复制需要保留的草稿，再用“重新加载（丢弃草稿）”核对最新内容，合并后保存。

## 经理保存

当前项目经理可以主动调用 `memory` 工具。普通成员无法调用，已停止或授权已失效的执行也无法调用。

```json
{"operation":"read"}
```

先读取返回的 `revision`，然后保存，例如当前版本为 3：

```json
{"operation":"add","target":"user","content":"用户偏好简洁的中文回复。","expected_revision":3}
```

`target` 为 `user` 或 `memory`；`patch` 用 `old_text` 精确匹配唯一一处，以 `content` 替换；`remove` 删除唯一匹配的 `old_text`。每次写入都必须携带最新的 `expected_revision`。冲突、锁定、容量超限或匹配不唯一时，整个操作失败，原文保留。只有工具成功返回后才能声称“已记住”。经理不能解锁或回滚历史。

记忆只保存稳定偏好和可复用经验，不自动复制完整聊天或临时任务状态。长期记忆属于参考资料，不能扩大项目授权或覆盖本轮用户要求。不要保存密码、API Key 或其他凭据。

## 生效与接入

每轮执行开始时读取一次快照，本轮重复生成输入时保持一致。新保存的内容可由 `read` 立即查询，并在后续执行和新项目的经理输入中自动出现。不会自动中断或重启正在执行的模型会话。

记忆由应用统一管理，不属于某一个 Harness 的私有记录。内置模块和自定义模块共用这个工具。自定义模块通过 SDK 的 `request` 获取输入，通过工具循环调用 `context.tool`；JSONL 模块通过 `tool_call` / `tool_result` 调用。仅支持纯文本回复、未实现工具调用的接入可以接收快照，但不能主动写入。

数据库位于应用数据目录的 `hub.sqlite3`，完整版本保存在 `long_term_memory_versions` 表中。备份应用数据即可保留记忆；不同数据目录彼此隔离。诊断包可能包含相关数据及已写入执行输入的快照，分享前请检查。
