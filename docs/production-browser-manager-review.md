# 正式制作、浏览器验收与经理统一调度修复

## 确认设计后执行真实产品开发
确认最终设计继续验证冻结文件和版本，但不再直接执行旧计划的演示首批任务。先创建经理安排任务的轮次，明确 delivery_stage=implementation；原批准计划作为需求参考，原静态演示步骤已经完成。经理须安排真实功能、交互、业务逻辑、必要后端与测试，并严格复现设计。复制演示、哈希一致只证明基线一致，不能代替真实功能实现。项目上下文公开阶段和验收政策；对已有 design_baseline 的会话同样追加正式制作政策。不会自动重新开启已完成旧项目。

## 浏览器截图作为单独能力
新增 browser_render(path,width,height) MCP 工具，仅接受本次项目或已批准基线内的本地 HTML。平台以本机 Edge/Chrome 无头模式、全新临时用户目录生成 PNG，不修改源码、不调整 Agent 整体权限、不禁用浏览器自身沙箱；图片永久保存在展示区。MCP 同时返回图片块、来源路径/哈希和截图尺寸。只读检查也可使用；原生启动错误会原样保留关键部分，不能用历史结论断言浏览器被禁。

本机已生成并目视检查 1280×800 的真实页面截图，不是结构模拟。截图只证明所选页面的渲染，不能代替全部页面验收或功能测试。当前工具不接受远程 URL，也不代理开发服务器；需要后端的交互测试仍由经理另行安排。API 文本工具通道只返回截图链接和元数据，不假定该模型支持图片；MCP 图像通道返回 PNG。

本机官方 Harness 源码显示 session.header.cwd 是冻结的创建元数据，恢复旧会话时 sandbox-policy 优先使用它，配置 workspaceRoot 仅为后备值。因此没有通过改写会话元数据强行改变沙箱，也没有清空上下文。权限审计现在同时记录实际边界、目标目录及是否一致；独立截图服务按当前任务目录授权，避免截图受旧会话目录边界影响。

## 经理决定检查职责
取消“正常完成后自动给 reviewer 发 check”和“异常执行自动挑 deepseek-8/首成员发 check”两条路径；新增一次性的 review_needed 事件通知经理。移除确认设计时默认将检查者改为 deepseek-3 的逻辑。预设 reviewer 不再独立构成自动检查门禁。经理主动安排检查后，仍要求检查完成、覆盖最新产物且风险为 low；在途、异常与未处理消息等完成保护保留。任务异常不得因为取消自动检查而冒充成功。

## 验证与限制
新增浏览器 4 项：真实渲染、路径/尺寸边界、原始错误保留、MCP 图像返回。新增经理调度 4 项：完成/异常都只通知经理、通知去重、预设检查者不触发强制任务、显式检查仍须完成。更新设计阶段切换测试。另回归 designs、roster_replan、harness、automation、integrations、live、message_receipts 与三项必需布局/阅读测试。

维护期间没有向当前项目发送消息、重开项目或执行真实模型推理。曾启动本机官方 Harness 的离线新建/恢复会话验证权限行为，未发送 session/prompt；只使用独立临时目录，未修改生产会话。后续生产任务需要重开桌面加载新版；已启动的提供商轮次不会在中途切换指令。

本轮相关测试合计120项通过（含 nine_deepseek 6项）；不代表所有历史测试全部通过。桌面构建与独立启动烟雾检查通过：ok=true、assets=10、simulation=false、native_available=true，退出码0。源码ZIP和三个桌面EXE已更新。
