# 用户选择项目目录后的授权衔接修复

根因：workspace接入保留旧项目authorized_cwd，新项目用户明确选定的目录仍被当作越界目录，无法批准执行。

修复：仅在user且confirmed=True的现有项目配置路径，允许将workspace边界重新绑定到已存在的新目录；不提升为full，不改变grant、独立预算或原会话。模型不能调用此配置路径。实际跨目录切换仍等待该提供商在途任务结束，避免改变正在执行的任务上下文。目录不变时更新时限不再误报“在途任务不能切换目录”。

同时核查生产库确认没有在途执行后，将本次最新讨论中已选定的工作目录同步到实际参与接入的cwd/authorized_cwd，其余配置保持不变；未启动模型、未自动批准计划、未重放任务。变更前配置保存在工作区work/project-scope-live-config-before.json，源码备份work/before-project-scope-fix.zip。

验证：目录重新绑定、权限/原grant保持、非用户或未确认拒绝、同目录在途设置测试13项（含基础设置）通过；集成21项通过。桌面打包与启动自检通过。
