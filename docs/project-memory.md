# 项目上下文与新一轮讨论

同一面板项目中，Argon的讨论、执行和普通消息使用同一持续提供商会话。新建讨论创建新的计划版本与审批记录，不创建空白记忆。新的执行工作流归属于同一面板项目时也沿用会话。不同项目分别保存，切回旧项目仍可恢复旧会话。

已有discussion、workflow及dialogue格式的会话记录按所属项目兼容读取，选择最近的对应会话，不删除旧记录。不会拼接全部旧执行记录到新提示词；通常仅发送新一轮消息。授权续期和权限设置仍单独核验，不以更换授权ID清空项目记忆。工具格式错误保留原会话，不自动重试或偷偷开启空白会话。模型侧自身的上下文压缩或服务端不可用不由本平台保证；会话恢复失败会报错，不退回空白会话重跑。

讨论阶段仍使用CLI的讨论/受限模式，验证官方init返回的模型与权限，拒绝工具步骤；保留记忆不等于批准新任务。用户必须明确批准当前计划版本才能执行。并发消息对同一Agent串行接收。

DeepSeek本地消息历史也兼容旧项目键，避免升级时丢失已有API上下文。原始会话ID、历史任务与讨论记录保留。

验证：171项回归通过。模拟提供商确认新一轮讨论实际走恢复会话路径；新输入不重复旧历史但可接上前一轮内容，另一项目不能读取该记忆。另验证讨论与执行共用项目会话、旧工作流会话兼容、授权续期不重建记忆、错误不自动换会话、DeepSeek旧历史兼容。真实本地记录的只读检查确认，当前项目的新讨论将选中现有Argon会话；未为本次验证增加付费推理。
