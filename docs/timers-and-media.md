# 持久定时提醒与成果展示

## 通知和暂停

没有 Agent 在执行不等于禁止启动。Supervisor 不依赖模型运行；活跃且已授权项目收到到期提醒，会唤醒目标，忙碌时排队。同一时间、同项目、同目标、同条件的提醒合并投递，保留各条附言。

全局／个人停止锁：提醒保存为 held，显示原因，不绕过锁。人工 paused、stopped 或未明确分类的 blocked：保持等待，不自动恢复。平台明确记录 pause_reason=wait_time/quota 的自动等待：条件满足后可恢复。授权到期或接入授权变化：不扩权，重试后显示需要检查。项目完成／取消后不启动旧工作。

注意：全局紧急停止原有语义还会把项目改成 stopped，解除锁本身不等于恢复项目。现已提供 stopped 项目的“恢复执行”入口；用户解除锁并明确恢复后，经理先核查现场，再继续。已取消或不确定的执行不重放。

## MCP

所有处于获准项目执行中的 Agent 都可用：

- schedule_wake(request_key, delay_seconds=60, recipient=自己, note='', interval_seconds=null, condition='time'|'quota_recovered')。相同项目、创建者、目标和 request_key 更新已有提醒。周期最短5秒；普通延迟支持数天，没有一天上限。
- timer_list()：本项目定时器和暂缓原因。
- timer_cancel(timer_id)：取消自己创建的提醒；当前经理可取消本项目提醒。用户面板可以取消所有提醒。
- publish_artifact(path, kind='image'|'webpage', caption='')：向用户展示当前执行目录中的图片／静态网页。产物快照保存于服务数据目录，不依赖源文件和临时开发服务。
- project_schedule_wake 作为兼容入口保留，使用持久定时器提醒当前经理，并推迟其原有定时巡检。

例：schedule_wake(request_key='build-check', recipient='deepseek-1', delay_seconds=1200, note='检查构建输出并向经理汇报；不要重复执行构建')。

讨论／普通私聊本轮原本禁止执行工具，仍遵守原有讨论和计划批准门禁。新增定时器不授予新的成员、提供商或模型费用权限。

## 额度恢复

使用提供商实际返回的 waiting_quota/retry_after、已读取的官方窗口或手动额度信息。已知恢复时间到达后允许尝试，通知经理这是“预计时间到”，不冒称额度已恢复。只有明确等待额度的原执行可走现有重试路径；失败／uncertain 执行不会自动重放。

quota_recovered 提醒在额度未知时保持等待，每10分钟再次读取已有信息，不发送推理探测请求。无法官方查询的连接仍需手动更新额度；不能承诺未知额度恢复后立刻检测。电脑休眠／服务关闭时不运行，恢复服务后合并处理错过提醒。

## 展示与面板

经理聊天区显示所有 Agent 发给用户的图片／网页卡片，附发送者、时间和附言，可打开原图或放大网页。网页是静态快照：保留同目录静态资源，禁止脚本、联网、表单和父窗口访问；需要后端的真实应用仍须单独运行。建议将网页放在专用产物目录；文件／静态资源最多30MB。预览链接使用随机不可猜测的本机 capability URL，不携带用户令牌，重启后仍有效。

右侧“定时提醒与自动唤醒”显示附言、时间、投递或保留原因，可取消。停止锁期间不能偷偷唤醒经理；配置变化通知仍会持久保存到允许交付的下一轮。

## 验证

无需模型账号：定时器合并、去重、休眠补发、重启恢复、全局／人工暂停、自动等待、额度未知／手动恢复、取消、当前项目成员权限、任意经理的工具可见性、网页快照和路径隔离；真实HTTP验证隔离CSP。浏览器在1440×900、1024×600、600×800检查图片／网页、定时状态、原始回复、发送框、滚动和草稿保留。未发送付费模型请求。

## 空闲、讨论与执行的区别（更新）

普通配置／额度告知不单独唤醒全员空闲的团队；只有讨论在进行也不触发后台实施调度，配置变化随用户下一条讨论消息交付。实施中完成汇报、明确额度等待造成的待处理工作、用户消息、已经设定的定时器、已批准项目的定期核查属于推进事件，仍允许唤醒，避免无人值守停摆。不能把“暂缓普通通知”变成“未完成项目永远不恢复”。

经理输出paused文字或JSON附加status字段不会修改平台状态；真正的人工暂停／停止来自平台动作。仅个别成员额度不足时，项目仍active，通知经理继续安排其它已授权且可用成员，原等待执行保留。运行状态工具提供retry_at及available，不把等待额度的成员显示成可用。

经理执行提示词明确说明schedule_wake的recipient、note、request_key和额度处理流程。精简经理策略当前382字符，作为持续会话策略更新；不把它重复塞进每条成员消息。未知额度恢复时间可使用time提醒经理定期核查，以原授权范围内未完成工作为恢复对象，结果仍受真实提供商确认，失败应延长间隔。额度恢复提醒指向已有waiting_quota执行时，只将附言加入它下次恢复输入，不重复创建任务，也不提前越过已知retry_after。

网页卡片和图片的放大按钮现在打开Hub内部预览窗，保留隔离和快照，不再依赖target=_blank由宿主选择浏览器。当前展示的是项目文件快照，不是任意外部网站或可运行后端。

## 关键成员等待和用户可见队列

只剩关键模型可以完成前置工作时，经理可以调用：

`schedule_wake(request_key="critical-model", recipient="当前经理ID", delay_seconds=3600, condition="quota_recovered", wait_for_agent="关键成员ID", note="检查该成员额度和在途任务，恢复后继续原分工")`

wait_for_agent只有当前经理可设置。平台保持active，并记录waiting_resource；等待期间不反复进行无事可做的定期巡检，但其它成员汇报和用户消息仍会被处理。quota_recovered检查wait_for_agent指定的关键模型，而非收件人的额度；恢复时间未知时，经理可选time在预计时间核查。到期自动唤醒，人工暂停和停止锁仍有效。取消对应提醒会解除自动等待标记，避免永久卡住。

用户在右侧“计时器与通知”直接查看计时器数量、目标、时间、附言、关键成员和等待原因，可取消提醒；也可展开积累的配置／额度／汇报通知全文。普通通知尚未交付时显示“待交付”；进入调度回合后显示“已排入经理回合”，这不冒称模型已经读到。浏览队列本身不会启动模型。

图片和网页卡片不会因查看而删除，可以反复打开；关闭再打开、刷新、重启后仍使用保存的快照。预览窗已处理快速关闭再打开时旧close事件清空新内容的情况。

关键成员等待若指定收件人为经理，且确实无法读取该成员额度／预计恢复时间，到期会提醒经理核查而非无限期静默等待；提醒明确标注“不代表已恢复”，仍不足时由经理延长下次提醒。普通quota_recovered提醒仍等待实际额度证据，避免直接空调用耗尽额度的成员。
