# 阅读状态与滚动修复

2026-10-19：自动刷新曾通过replaceChildren重建列表，展开恢复与懒加载异步toggle之间产生短暂高度塌陷，浏览器随之重置滚动。现在公共列表渲染复用未变化行，保持节点、展开正文、焦点、文字选择、用户调整高度与内部滚动；变化行在插入前同步填充已展开内容，插入后恢复内外滚动。状态保留按当前项目隔离。分页按钮使用最新事件绑定，避免旧闭包丢失最新历史。

同一修复覆盖经理沟通、群聊动态、任务台账、草案预览、审计、唤醒及汇报列表，实际模型输入抽屉也同步修复。额度横幅在内容未变化时不重复重建按钮。

长文本和实际Prompt阅读区支持纵向拖动调整，最大65vh；经理正文最小280px，实际Prompt最小180px；短屏降至120px。草案任务预览由140px调整为45vh。

验证：真实Edge回归逐一检查七类列表刷新/追加后节点身份、展开、内部滚动不变；状态变化时同步展开并保留内部滚动；阅读区域尺寸与可调整属性；既有九Agent界面与输入草稿保留测试通过。JS语法通过。没有调用模型，没有重放任务。


## 后续布局修正：阅读区与回复区分离

先前放大正文并未验证长审批卡片与回复框同时出现，造成布局挤压。经理面板现使用独立 managerReadingArea，原始回复、草案、审批说明和历史项目均在其中滚动；回复框固定留在阅读区之外。补齐flex高度链的min-height:0，防止子内容撑破外层隐藏裁切。短窗口采用紧凑回复框和可滚动经理控制条；窄窗口保留明确聊天面板高度。

真实Edge测试同时放入200行原始回复、8项长任务和长审批说明，在1440×900、1024×600、600×800窗口验证：回复及发送按钮可见、阅读区高度大于80px且可以实际滚动、原始文字仍在。原有七列表阅读状态和九Agent草稿测试继续通过。项目AGENTS.md明确要求后续UI改动必须执行这三类回归，不能仅检查语法或节点存在。
