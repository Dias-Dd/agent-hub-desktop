# Agent面板与两步添加引导

入口：左侧▦称为「Agent面板」，管理入口位于面板左上角。移除此前左侧独立接入按钮和三栏配置大表单；界面不提供手动添加提供商。

当前9个Agent时，卡片区在常规桌面窗口约占可用面板宽度60%、高度约60%，四周约20%留白。10–16个Agent逐步加宽，更多时使用全部可用宽度；数量很多时滚动。短窗口/窄屏优先保证内容可访问，不强求20%的留白。

卡片保留名称、模型、忙闲与档位。点击「详情」查看完整任务、额度、实际输入及停止操作；详情是独立、有滚动路径的弹窗，不撑大卡片，也不改变聊天布局。

管理窗口列出现有Agent，普通身份可删除（归档，历史不删）；当前经理与仍执行中的身份不提供误删入口。添加步骤：选择既有接入→下一步读取模型→选择模型并命名→添加。名称默认模型名加递增序号，相同模型可重复添加，后端原子生成不同ID与默认序号。

模型只能从目录选择。WorkBuddy读取官方CLI帮助中的受支持模型列表；Ori读取OpenRouter公开模型目录；未安装Claude Code提供官方工具别名（不代表本机已安装或账号有权限）。新连接启用确认默认不勾选。添加本身不发起模型推理。

模型、名称与向导步骤在轮询、返回上一步、刷新后保留；授权确认不跨刷新保留。异步目录/档位请求绑定当前选择，过期结果不覆盖新选择。现有档位选择仍在卡片上，新增OpenCode/Ori时可自动读取官方档位信息。

验证：24项接入、向导、必需UI与演示回归通过；覆盖3/9/12/36个Agent、三种窗口、9个时四周留白、36个时滚动、详情不撑大卡片、删除与添加路由、编号、刷新保留草稿、不默认授权。模型目录只读验证：Ori公开目录470项、WorkBuddy本机CLI9项、Claude Code官方别名3项。没有付费模型推理。

原始UI源码备份：work/before-agent-panel-ui.zip。后端原有管理接口保留兼容，新页面只使用预置选择与integration_wizard_add；该接口会校验模型属于相应目录。

## 项目经理
当前项目经理卡片显示紫色高亮边框。在管理 Agent 中选择项目经理并点击“设为经理”；只影响当前项目，保留讨论与任务记录，待处理的经理消息转交新经理。经理或目标 Agent 正在执行时须等本轮结束再切换，避免双经理并发；执行中的项目只能选择已获该项目授权的接入，不会自动新增付费授权。

验证：经理选择持久化、历史保留、忙碌保护及用户权限测试通过；浏览器验证高亮与完整候选列表，三种窗口布局与滚动回归通过。旧 planning/workflows 测试仍引用已删除的 sol 身份，存在旧夹具失败；本次已运行现行九 Agent、经理消息及接入测试。

## 配置变更合并通知
Agent 的新增、移除、名称、模型、接入、角色、档位及当前经理变更，会按项目持久保存。同一成员只合并最终净变化；改回原值、尚未通知就新增后删除不会产生通知。活跃项目仍有实施执行在运行时，在最后一次修改约5秒后通过队列发送一条汇总；全员空闲或只有讨论回合时先积累，随下一条用户消息、工作汇报或定时唤醒一起交付；连续操作最多约20秒汇总一次。如果经理因其它消息先被唤醒，已有变化随该轮一并提供。不活跃项目不额外唤醒模型，下一次讨论或经理调度时附带汇总。经理切换后通知当前经理。通知不会给新成员自动授予项目执行权限。

验证：21项接入测试（含批量合并、去重、恢复、撤销、项目隔离、当前经理路由、讨论提交失败保留通知）通过；6项九Agent后端与8项经理输入回归通过。未调用付费模型。
