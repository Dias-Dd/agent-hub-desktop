# Codex 真实任务执行

现已实现官方 ChatGPT 登录 → 指定模型验证 → 真实任务队列 → 文件/命令执行 → 最终事件回传。支持 sol-1 / sol-2 的 GPT-6.1 Sol 和 astra 的 GPT-6 Astra，effort 固定 medium，启动前均以官方模型目录核实，不替换模型。

## 怎么用

1. 启动 Hub 并连接仪表盘，在顶部“真实任务执行”展开配置。
2. 输入**已存在的绝对工作目录**；选择“完全访问”或“仅工作区写入”。完全访问相当于当前 Windows 用户的文件/网络权限，不自动获得管理员权限；工作目录只是操作起点，不能限制完全访问模型读取或改写其它路径。
3. 设置这次允许的任务数量（0–100）和单任务时间预算（30–3600 秒），勾选授权与启用，保存。权限、目录和次数预算会持久保存。
4. 在“提交真实开发任务”选择 Agent，写明任务与验收要求，勾选批准并提交。无需在每条 shell 命令或文件修改时再次点确认。也可先在旧任务区分配给真实身份，再点击“查看并授权真实执行”。
5. 查看真实状态、命令输出、文件改动、最终回复和实际 token 用量。需要停止时点击“请求停止”。

本机当前实例按用户明确授权设置为：完全访问，工作目录为项目下 projects，任务次数预算 3，每项最多 900 秒。此设置没有额外发起任务。下载包的新数据目录仍默认关闭，需要初始化。

**Antigravity 五个身份也已有真实适配器，但当前受地区/额度限制，见 ANTIGRAVITY_EXECUTION.md；DeepSeek 消费者仍是模拟。** 混合模式下总体区域显示系统对真实执行记录的汇总，不冒充真实项目经理。聊天窗口里的普通排队消息不自动触发推理，旧模拟消息也不会转换成真实工作。立即消息会请求中断正在运行的真实任务，但不会在没有新任务授权时自行执行其内容。

## 权限和额度

执行器调用官方 `codex app-server --stdio`，先检查 `account/read` 为 ChatGPT 登录，再检查指定模型及 medium、实际额度窗口。没有登录或额度无法核实时，不开始推理。API Key 登录会被拒绝，不自动切换到 API 付费路线。

完全访问使用 thread/start 的 `sandbox: danger-full-access`、`approvalPolicy: never`，并校验官方返回的有效权限/模型；turn/start 同时声明 `sandboxPolicy.type: dangerFullAccess`。这是官方支持的权限模式，不代表能够突破操作系统或组织策略。若服务端仍提出交互审批，Hub 不自动额外授权，任务会记录原因。

这次授权的**任务次数预算**在任务排队时占用。未开始的任务可取消释放，启动后不自动退款。每项最多启动一个模型回合，回合内部可能包含多次推理与工具步骤，因此次数不是 token、美元或实际模型请求数量硬上限。Codex 使用账号额度，Hub 不购买额度、不兑换重置券、不自动补款；需要金额硬限制时应另行使用提供商支持的计费控制，本版本不伪称已做到。

每次任务需用户在具体任务旁点击批准，权限配置可以一次保存，不逐条审批命令。用户在本次聊天中已明确授权完全访问及实现验证；开发验收仅发起一次真实 Sol 工作回合。

## 执行、停止与恢复

同一时间只执行一个真实任务，避免两个模型同时修改同一目录。`queued → running → completed / failed / interrupted / uncertain`。完成表示官方回合完成，不能保证用户的全部验收条件满足；应检查模型报告、命令退出码和文件。任务启动/结束对应写入正常任务、消息和审计记录。实时细分百分比不伪造，工作中保持 working，结束后更新。

命令、文件改动和计划以官方 item/事件为证据，不保存原始 reasoning。最终回复及 token 用量保存到 SQLite。页面展示最近 30 项真实执行、150 条事件；更早记录仍在数据库中。每项授权绑定输入、模型、cwd 和权限的不可变快照，修改配置不能悄悄扩大已排队任务的权限。

停止/立即消息/时间预算到达时，发送 `turn/interrupt`，收到 `turn/completed` 的 interrupted 才确认中断；超时或断线标 uncertain，绝不自动重跑。中断不会撤销已经写入的文件。服务重启后运行中任务也标 uncertain，等待人工检查；尚未开始且已授权的队列可继续。

Windows 上为执行器 CLI 建立受管 Job，Hub 进程退出时关闭其拥有的 CLI 子进程树。操作系统外部服务、网络请求和模型已完成的副作用仍无法通过关闭本地进程撤销。本项目不修改用户全局 Codex 配置，也不读取/导出 OAuth 凭证。

## 实际验证

本机 GPT-6.1 Sol + medium + 完全访问，完成一个真实任务：创建 `projects/codex-smoke/arithmetic.py`、`test_arithmetic.py` 和 `RESULT.txt`，通过官方命令工具运行 `python -m unittest -v`，两项测试通过。之后由 Hub 开发侧独立复跑，也为两项通过。执行约 40 秒，官方报告 70280 total tokens（包含缓存输入），不是美元费用。详情在 `codex-live-test.json`。

GPT-6 Astra / 第二个 Sol 的模型访问已由同一官方目录验证，但没有为重复验证额外启动真实推理。官方中断链路由模拟协议事件测试覆盖，本轮未额外消耗额度做真实取消实验。Windows CLI Job 及 OAuth/额度路径已做只读实测。
