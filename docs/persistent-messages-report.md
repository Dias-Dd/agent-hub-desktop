# 持续会话与项目管理更新（2026-10-18）

## 使用

顶部“创建新项目”生成独立目录和历史分组，不调用模型。选择项目，与 Argon 讨论并确认“按计划执行”后才开始。项目下拉框分别显示任务、消息、讨论和执行记录；旧记录仍可查看。

## 会话与消息

Codex 保存 thread ID，通过官方 thread/resume 续聊；Antigravity 保存 conversation ID，通过官方 --conversation 续聊。各 Agent、项目和授权分别管理。后续追加新任务、新消息与必要变化；重启保留会话，未知执行不重放。

DeepSeek 文本 API 在本地保存历史，按官方请求格式携带历史；费用预留包含历史输入，旧上下文审批不会直接用于更新后的会话。该连接器仍不具备 CLI 工程执行能力。

执行者通过 report_result 提交简短汇报，提供商确认本轮结束后投递完成事件。Argon 空闲即领取，忙时合并；不会因任务创建顺序漏掉晚完成的检查。

忙碌成员可以接收排队正式任务。同身份串行；后续正式任务等待上一正式任务成功。前置失败先通知经理，不盲目启动。Argon 可以取消未启动的排队任务。

全部空闲且未报告完成时，自动补查一次；仍无进展明确显示需要关注，不无限唤醒。用户也可点击“唤醒 Argon 检查一次”。

## MCP 与流程

- project_status：忙闲、排队数、可用性、依赖、证据、额度快照。
- project_mailbox：发送者、接收者、消息状态、正文和分页。经理可读项目对话，成员只读自己的对话。
- send：同项目队列质询和回复；沟通本身不授予实施权限。
- project_assign：只有 Argon 在批准范围内正式派工，kind=work/check。
- project_set_role：调整已授权成员职责和检查者。Flash-3 是默认测试角色，不固定绑定；改角色不会获得经理权限。
- project_cancel_task：经理取消未启动的任务，保留记录和审计。
- project_complete：Argon 提交完成证据；有在途任务、新消息、未覆盖检查或严重风险时拒绝完成。成功保存完成状态和总体进度。

系统提示词说明流程，平台执行身份、权限、预算、队列和停止规则。质询使用 Codex read-only 或 Antigravity plan+sandbox；不改文件、不派工。质询只能回复原提问者或上报 Argon，正式任务优先，仍受消息链和预算限制。

Sol-1、Sol-2 和 Astra 当前均为 medium。

本机官方 Codex 接口已恢复既有会话，并确认 MCP 工具连接，没有启动推理。实际 Argon 第17轮与第16轮使用相同会话，完成一轮，并通过 MCP 给 Flash-3 分配了补充只读检查；此期间新增 Codex 推理调用为0。

随后项目收到用户停止操作，保持 stopped，不继续或重放。项目完成 MCP 的完整往返通过本地测试验证，不把被停止的实际项目说成已经验收完成。

## 说明
